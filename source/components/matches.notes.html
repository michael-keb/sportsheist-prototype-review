Two pushed screens: the club's fixture list, and the record of a finished match. Matches is not one of the five tabs and has no designed frames, so both are new — built entirely from the established dark-mode language.

What you're looking at

A screen with no frames behind it

Matches is not a navigation destination. It is not one of the five tabs, it has no Figma frame, and in the checked-out source the matches body renders an empty container. What does exist is a written spec and a set of API fields. Both screens here are therefore built as pushed screens — a back control, no tab bar — because that is the only honest reading of a surface reached from somewhere else.

The fixture list carries a three-way filter and, on the Live tab, the empty state you will see for most of any given week. The detail screen carries the result, the match record, and the member playoff attached to that match — the part of this screen that is genuinely SportsHeist rather than a generic scoreboard.

Clubs appear here more often than on any other screen, so the crest plate does a lot of work. No club crest artwork exists anywhere in the export, so every plate currently holds a three-letter code — but the plate itself is now the canonical one, and real artwork can drop into it without the layout moving.

Provenance

What is reused and what is new

Reused from the Figma file

  • Tokens — surfaces, hairlines, accent, hero gradient, radii, type scale, copied verbatim from the sampled set
  • Screen title — 34/800 uppercase at -.025em
  • Section label — 18/600 at the gutter, no adornment
  • Section container — #080A0C, 1 px hairline, R16, 12 px padding
  • Crest plate — the canonical light plate settled in Club selection, ported here verbatim rather than reinvented
  • Status pill — the LIVE NOW geometry, type and dot
  • Icon button — 38 px circle with a 1.9-stroke glyph
  • Card and row — R16 card on #1C2129; rows at 10–11 px with a --line-soft top border and none on the first
  • Podium — the plinth construction from the Merits proposal: size, rank chip, ring opacities
  • Field gradient and triangles — reused for the result lockup
  • Photography — three portraits from the export set

New in this proposal

  • Both screens — Matches has no designed frame and no built screen; the fixture list and the match record are new
  • Code fallback content — no crest artwork exists in the export, so every plate on this screen holds a club code (BAR, RMA) rather than a crest
  • Fixture card — the three-column lockup that holds a kick-off time or a score in the same slot
  • Outcome without colour — winner and loser expressed as name weight, figure opacity and a named pill only
  • Segmented filter — Live / Upcoming / Finished, built from the tab-bar active rule
  • Quiet and small status-pill variants — Full time and Pending at 26 px on #13171E
  • Empty live state — block, glyph, heading and the promise that the fixture appears the moment it kicks off
  • Result lockup — the hero language used as a scoreboard, without peaks or prop
  • Pending score treatment — muted en-dashes and a Pending pill for a finished match with no result returned
  • Member-of-the-match award — the named pill and the caret that points at the winner's column
  • Pushed-screen chrome — back control and no tab bar, because Matches is not a tab

Reconciled since the first review. This screen was built before the crest plate was settled, and it originally drew its own: a dark #13171E plate with a 1 px white hairline at 56 / 40 / 24 px, with the winner marked by brightening that hairline. It has now been brought onto the canonical light plate from Club selection — the same ground, the same inner hairline, the same proportional radius and padding, the same square fit — with its sizes remapped to the sanctioned 28 / 40 / 64 px. Two things followed from that. The plate no longer carries any per-club or per-state variation, which is the whole point of it: contrast is now a property of the plate, identical for every club, rather than of whichever crest happens to be in it. And because the plate may not take a ring, the winner's emphasis moved entirely onto the name, the score figure and the Winner pill, which were already carrying it. Nothing else on the screen changed.

Decisions

What we need from you

  1. Where do club crests come from?

    There is no crest artwork anywhere in the export, so every plate on this screen falls back to a club code — BAR, RMA, ARS. The plate is now the canonical one and is sized so artwork lands in it without the layout moving, but we still need a licensed source and an ingest process before build — including the rule that rejects a pale, transparent-background crest that would disappear into the light plate. Until then, confirm the codes are correct per club: they are currently ours.

  2. What is the currency called, and is it the same one?

    The playoff prize rows read 1,000 points. The Merits tab calls the currency Merits, the API calls it Reputation Points, and elsewhere it appears as Credits, Participation Credits, Participation Deposit and a legacy BOND. This screen uses points because that is the spec's word, but if a playoff prize pays the same currency the leaderboard ranks on, it must use the same name. If it is a different quantity, it needs a different one.

  3. Why is every podium score zero?

    All three members read 0 points — that is what the source data says. The build handles it by making rank, scale, ring and the named award carry the outcome, so the screen is not broken. But three members tied on nothing does not explain how a member of the match is chosen. We need the scoring rule, and whether the score should be shown at all if it is not what decides the winner.

  4. The location field is unusable as it stands

    The match detail row currently prints Emi, Mimasaka, 709-4292, Japan for a Champions League quarter-final. That is the value in the source — an unfiltered address string, and for a fixture that would not be played there. Either the row shows the stadium name and city, or it comes off the screen. It should not ship a postal address.

  5. Is Matches reached from the tab bar or from a club?

    Matches is not one of the five tabs and the current source renders it empty, so both frames are built as pushed screens with a back control and no tab bar. If Matches is meant to be a first-class destination it needs a hero, a place in the navigation, and a sixth slot in a bar that already holds five.

  6. What does a live match actually look like?

    The Live filter is built and its empty state is designed, but there is no live fixture card: nothing in the source defines what changes while a match is in play — a clock, a period marker, a score that updates, a link into the room talking about it. That card needs designing before the filter is worth shipping.
