This file specifies all three — ten empty states, four loading states, six errors and two banners — so no screen has to invent its own.

System · states

States

Ten empty states, four loading states, six errors and two banners. Every one carries a heading, a line of explanation and — where an action exists — one primary action. Where no action exists it says what will happen instead, rather than leaving a dead end.

Empty states

One panel, ten illustrations. Every illustration is drawn in the same 132 × 88 frame on the same ground line, from the peak geometry already in the brand: surface fill is context, accent wash with an accent stroke is something that exists, and a dashed accent outline is something that should exist and does not yet.

Loading

Two markers only. A ring where a control or a line is waiting, three peaks where a whole panel or a whole screen is waiting, and skeletons where the shape of the answer is already known. Both markers are SVG-timed, so there is no keyframed animation to leak past prefers-reduced-motion.

Skeleton · idea card

Bone positions are the idea card's own: three 22 px stacked avatars, a 17 px title over two lines, body at 13 px, the meta row, and the sunken gauge panel with its 64 px ring. Nothing shifts when the content arrives.

Skeleton · ranked rows

Rank slot, 34 px avatar, name over club, score — the merits row exactly, at 11 px / 12 px padding with the same rgba(255,255,255,.045) hairline between rows. Bones are white at 5.5% with a white at 6% sweep, so the same bone works on the card, the section and the sunken panel. The live build's grey-300-on-grey-100 shimmer is a light-theme skeleton.

Spinner · the ring

28 · 20 · 16. A 90° accent arc on a white-18% track, one turn every 0.9 s, round cap. Stroke thickens as the ring shrinks so the arc keeps its weight.

Replaces WLoading, whose color ?? Colors.blue default paints a Material #2196F3 dot-ring in every waiting state in the app — a hue that appears nowhere else in the brand. On an accent fill the ring inherits #0B0E06, not white.

Panel · three peaks

Counting the ballot

1,284 Barcelona members voted. This takes a few seconds the first time.

Used where the shape of the answer isn't known, so a skeleton would lie. Where it is known, use a skeleton — it's faster to read and it doesn't move the layout.

In-button · width preserved, control disabled

Press Cast vote or Link a member. The label is hidden with visibility, so it keeps its box and the control cannot change width or jump the row. The spinner takes the label's ink — #0B0E06 on the accent fill, white on the ghost. aria-busy="true" goes on the button and pointer events stop, so it can't be submitted twice. The ghost button is parked in that state for comparison.

Error states

Same panel as the empty states, with the icon tile instead of an illustration — an error is a thing that happened, not a space that's unfilled. Each one says what happened, why, and the one thing to do next. No apologies, no blame, no raw server strings, and no OOPS!. Errors that interrupt a task in progress use the dialog shell instead; these are for when the error owns the region.

No connection

You're offline

Nothing has reached the server since 16:42. Everything already loaded stays readable — posting and voting need a connection.

Request failed · with retry

Your vote didn't send

The server took too long to answer — usually a brief drop rather than anything wrong with the ballot. Your vote is still saved on this device, so nothing is lost.

Retry is the primary action and it uses the in-button spinner, so the member can see the second attempt happening without the panel redrawing.

Not found

This idea is no longer here

It was either withdrawn by the member who posted it, or removed after the vote closed. The rest of the war room is unaffected.

No permission

Voting is for verified members

Your Barcelona membership hasn't been checked yet, so this ballot is read-only for now. Verification takes about a day once your membership number is on file.

Replaces the OOPS! modal, which shows the raw HTTP 403 body — You do not have permission to access this resource. — with no explanation and no route out. A 403 is almost always a missing step, so the copy names the step and the action completes it. The tile stays neutral: nothing has failed and nobody has done anything wrong, so red would be a lie.

Session expired

You've been signed out

Sessions end after 30 days, or when you sign in on another device. Everything you posted and every vote you cast is saved to your account.

Something went wrong · last resort

This screen didn't load

Something failed on our side and we don't yet know what. It's been logged as 8F2-4471 — quote that reference if you get in touch.

The only state that admits it doesn't know the cause. It earns that by giving the member a reference number, which turns an unhelpful message into a support ticket. This is the last resort — any error we can name gets one of the five above.

Offline and stale data

A banner is for when the screen still works but something about it is qualified. In-flow, so --r-panel and the sunken fill — never the card radius, and never red: neither of these is a failure.

What you're looking at

The screens nobody designs, designed

In the current build these moments are unowned. An empty list is a pure #000000 panel with one shouted line of Bebas and nothing to do. A failure is a modal titled OOPS! carrying whatever text the server returned. A wait is a Material blue dot-ring. None of them is in the brand, and none of them tells a member what to do next.

The most expensive one is the empty ballot. NO PROPOSALS AT THE MOMENT is the first thing a new member sees after they join a club — the moment the product has to explain itself — and it currently explains nothing and offers no action. In this proposal that one state gets a real welcome: what this place is, how the week works, and a button that puts the first idea on the board.

Everything here is built from parts that already exist. The empty-state illustrations are the hero banner's angular peaks, redrawn at small size. The loading marks are the same two marks specified in the Dialogs file. The panel is the bordered section container. No new colour, no webfont, no illustration library.

States

All eighteen, and what each says

The illustrations are one system, not ten drawings. Every one is set on the same 132 × 88 frame, seated on one ground line at y = 72, and drawn with three marks only: surface fill #1C2129, no stroke is context — the range behind; accent wash rgba(155,226,34,.18) with a 1.8 #9BE222 stroke is something that exists; a 1.8 accent stroke dashed 5 5 is something that should exist and does not yet. Nothing curves except the circles the brand already uses for members and the search lens.

Copy as written. One primary action, or a stated outcome where none is possible.

What is reused and what is new

Reused from the Figma file

  • Peak geometry — the hero banner's three acid peaks, redrawn small
  • Section container — the bordered wrapper #080A0C with a 1 px hairline
  • Surfaces, radii, type scale — sampled, not approximated
  • Accent and semantic red — #9BE222 and #E2564A, nothing else
  • Icon style — 24-box, 1.7 stroke, round caps and joins
  • Tab bar — the floating pill, active tab with icon and label

New in this proposal

  • The illustration system — one frame, one ground line, three drawing rules; ten illustrations that read as one family
  • The welcome state — a real first screen for a new member, replacing NO PROPOSALS AT THE MOMENT
  • The no-action line — a stated outcome where a button would be dishonest
  • Skeleton geometry — bones matched to the idea card and the ranked row
  • White-alpha bones — rgba(255,255,255,.055) replacing the grey-300-on-grey-100 shimmer, which is a light-theme skeleton
  • Error copy — six states written as what happened, why, and the one thing to do next
  • Reference number on the last-resort error
  • First-load screen — no equivalent exists
  • Offline and stale-data banners — no equivalent exists

Decisions

Five things we need from you

  1. Can a member open a locker room, or only the club?

    If members can, the primary action on No rooms open right now should be Start a room — a far better empty state than a reminder. We couldn't confirm it from the exports, so it currently reads Tell me when one opens, which is safe but weaker.

  2. Does an offline vote really send itself later?

    The offline banner promises Your vote will send itself when you're back, and the failed-request state promises the vote is saved on this device. Both need an outbox that survives the app closing. If there isn't one, the copy has to change to "you'll need to vote again" — which is worth avoiding, because it is the difference between a trustworthy app and a lossy one.

  3. What does a 403 actually mean to a member?

    We've written the permission state as one specific thing: membership not yet verified, with the action that clears it. If the same 403 also covers being suspended, being in the wrong club, or a closed ballot, each needs its own heading and action. One generic message here is how the app ended up with OOPS!.

  4. Is there a reference number and a place to send it?

    The last-resort error shows 8F2-4471 and a Contact us button. That assumes the client can read an error id from the logging layer, and that there's an inbox behind the button. If either is missing, the state loses the one thing that makes it useful.

  5. What are linked members allowed to do?

    The empty state says linked members' votes can be cast together. If linking is really about a shared season ticket and not about block voting, that sentence is wrong and the whole state needs rewriting — it's the only explanation of the feature a member will ever read.
