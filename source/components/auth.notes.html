The screens a person sees before they are signed in: the Get Started welcome, Log in, the password-reset dead-end that ships today, and the password recovery we propose to replace it with. Nobody has an account yet, so there is no tab bar and no way out except forwards.

What you're looking at

One frame reproduced, two rebuilt around it

Get Started is the only pre-auth screen that has already been designed in the new brand, so it is reproduced here rather than reinterpreted — the black canvas, the acid angular field, the photography standing in front of it, the monogram-and-wordmark lockup, the greeting and the dark pill with its leading acid arrow are all off the export. Sign in and Reset password are new work, built to sit beside it in the same language.

Both new frames are assembled entirely from the Forms kit — the same field, the same 52 px control, the same validation row, the same action footer — so nothing here is a one-off. That matters because the pre-auth flow is where the current app is least consistent, and four specific inconsistencies are fixed on these three screens rather than merely noted.

The two new frames also carry their own states inline: an invalid-credentials form, a submitting form and a code-sent confirmation, each captioned. A spec sheet at the foot of the page records what was standardised and what it replaced; it is documentation for this review, not a screen.

One frame here is not a proposal at all. Password reset · shipped today is the screen that is in the live build right now, and it is included so the review does not imply a journey completes in the app when it does not. Tapping Forgot password? on Log in opens a screen with three things on it — a title, one sentence, and a link that hands you to the desktop website and drops you back at Log in. There is no email field, no code, no confirmation, and no way to finish inside the app. The frame after it, Reset password, is what we propose instead. They are the same journey twice, and the pair is the point.

Provenance

What is reused and what is new

The split here is unusually clean. Get Started (AU-02) is a reproduction — that frame exists in the new brand and is rebuilt from it. Sign in (AU-05) and password recovery (AU-06 + AU-07) are new: the screens exist in the shipped violet app, and their strings and behaviour are honoured, but nothing about how they look here comes from a designed frame.

There is a third category, and it applies to exactly one frame. Password reset · shipped today is neither a reproduction of a designed frame nor a proposal — it is a record of current behaviour. Its copy, its layout proportions and its single link are taken from the running code, and the only thing changed is the palette. It is in the library so the Reset password frame beside it cannot be mistaken for something that already works. Read the two together: the shipped one is what a member gets today, the proposed one is what we are asking to build.

Decisions

What we need from you

  1. Does password reset move into the app, or stay on the website?

    This is the biggest question on the page, and the two frames put it side by side. Today the app cannot reset a password: the screen says Please go to Sport Heist website to reset your password, opens the browser, and returns you to Log in. A full in-app reset is routed in the code — request, six-digit code, new password — but nothing navigates into it, so none of it runs. We have designed the in-app version because handing someone who has just failed to log in over to a browser is where accounts are abandoned, but we have assumed the reset comes in-app and that is a build decision, not a design one. If it stays on the web, the shipped frame is the answer and the Reset password frame comes out of the library — but the copy still needs rewriting, because it names no destination and gives no reason.

  2. Which spelling of the product name is correct?

    The shipped reset screen says Sport Heist, two words with no s on Sport. Elsewhere the same app says SPORTSHEIST in the logo, Sports Heist in body copy and Sports Heist(stg) on the iOS notification alert. That is four spellings in one product. The library uses SportsHeist, one word, everywhere except on the frame that records current behaviour, where the shipped string is quoted as-is.

  3. Sign in, or Log in?

    The live flow uses three verbs for two concepts, so one pair has to win. We picked Sign in / Sign up because two of the three shipped strings already use it and Log in / Log up is not a pair. It is a five-minute change now and a find-and-replace across every string later, so it is worth confirming before build.

  4. Can we have the real logo as a vector?

    The monogram is drawn from the peak motif and the wordmark is set in the system stack, because the live app ships the lockup as a raster and this library has no webfonts. Both are placeholders. Everything else on the frame is sampled, so this is the one element that will visibly change when the real asset lands.

  5. Can we tell a member which credential was wrong?

    The API returns one undifferentiated failure, so both fields take the error ring and the message admits it. That is honest but it is a poor experience, and it is the difference between one error design and two. If the server can distinguish an unknown account from a bad password, we would rather it did — with the usual caveat that saying no such account out loud leaks who is registered.

  6. Is the recovery code six digits, and does it last ten minutes?

    The screen states both, because a recovery screen that does not say what is coming or how long it lives is a support ticket. Both values are assumed, as is the no-reply@sportsheist.com sender. If the real mechanism is a magic link rather than a code, this frame and the one after it change shape.

  7. How should a resend be rate-limited?

    Send it again is a plain link with no cooldown, because no rule exists in the code. Most products disable it for 30–60 seconds and count down. Give us the window and the link will show it.

  8. Is the identifier label Email or Username or Username or Email?

    The screenshot says one and the repository string says the other. We used Email or Username, from the capture. One of the two should be retired before either is translated.

  9. Does registration exist as a designed flow?

    Sign up is offered from Sign in and, in effect, from the Get Started pill, but there is no designed registration in the file — and the club-selection and onboarding screens imply a multi-step one. Whether Get Started leads to registration or to sign-in changes what that pill should say.

  10. No SSO, biometrics or "remember me" — confirmed?

    The live screen has none of the three, so neither does this one. Face ID in particular changes the whole action stack, and it is far cheaper to design in now than to retrofit after build.

  11. Should the Get Started prop be re-cut?

    The supplied cutout is feathered rather than cleanly masked, so its alpha is lifted in the browser and its edges masked to stop the acid field reading through the figure. It works, and it is the right fix for an asset we cannot re-cut, but a properly masked PNG would be cleaner, sharper and cheaper than an SVG filter plus two masks on a 440 px image.
